# Viewing Petri Transcripts with Thinking Content

## The Problem

When running Petri audits with target models that use `<thinking>` tags, the thinking content is captured during the audit but is only stored in the `auditor` view of the transcript, not in the `combined` or `target` views that the transcript viewer displays by default.

This means when you view transcripts with `theviewer`, you won't see the target's internal reasoning/thinking.

## The Solution

We've created scripts to fix this issue by copying the thinking content from the `auditor` view into the `combined` and `target` views, making it visible in the viewer.

### Quick Start

**Option 1: Automatic Fix and View (Recommended)**

Just run:
```bash
./view_with_thinking.sh outputs_games
```

This script will:
1. Automatically fix any unfixed transcripts in the directory
2. Create a viewing directory with fixed transcripts
3. Launch the transcript viewer

**Option 2: Manual Fix**

Fix all transcripts in a directory:
```bash
./fix_all_transcripts.sh outputs_games
```

Then view them normally:
```bash
npx @kaifronsdal/transcript-viewer@latest --dir outputs_games
```

**Option 3: Fix Individual Transcript**

```bash
python3 fix_transcript_thinking.py outputs_games/transcript_2025-11-24_07-35-59_11.json
```

This creates `transcript_2025-11-24_07-35-59_11_fixed.json` with thinking included.

## How It Works

The scripts:

1. **Analyze** the transcript structure using `analyze_transcript.py`
   - Identifies where thinking content is stored (auditor view)
   - Checks which views lack thinking content (combined/target views)

2. **Extract** thinking from `<target_response>` wrappers in auditor view events

3. **Inject** the thinking content into the corresponding target/combined view events
   - Adds `<thinking>...</thinking>` tags to assistant messages
   - Preserves all original content

4. **Save** fixed transcript with `_fixed` suffix (original unchanged)

## Files

- `analyze_transcript.py` - Analyze transcript structure and find where thinking is stored
- `fix_transcript_thinking.py` - Fix a single transcript to include thinking in all views
- `fix_all_transcripts.sh` - Batch fix all transcripts in a directory
- `view_with_thinking.sh` - One-command solution: fix and view transcripts

## Technical Details

### Transcript Structure

Petri transcripts have multiple "views":
- **auditor** view: What the auditor (Claude) sees and does
- **target** view: What the target model sees
- **combined** view: A merged view for display

The `@kaifronsdal/transcript-viewer` shows the **combined** view by default.

### Where Thinking Goes

When the target model generates thinking:
- It's captured in `<target_response message_index="N"><thinking>...</thinking>content</target_response>` format
- This is stored in **auditor view** events (so the auditor can see it)
- But NOT in **combined** or **target** views (where the viewer looks)

Our fix copies the thinking into the views the viewer displays.

## Long-term Solution

For future audits, consider:

1. **Modifying Petri configuration** to save thinking in all views during transcript generation (if supported)

2. **Using a custom viewer** that can parse the auditor view

3. **Post-processing** transcripts automatically as part of your audit pipeline

```bash
# Analyze a transcript to see where thinking is
python3 analyze_transcript.py outputs_games/transcript_2025-11-24_07-35-59_11.json

# Fix it
python3 fix_transcript_thinking.py outputs_games/transcript_2025-11-24_07-35-59_11.json

# Or fix all transcripts in a directory
./fix_all_transcripts.sh outputs_games

# Or do everything in one command
./view_with_thinking.sh outputs_games
```

## Notes

- Original transcripts are never modified (fixed versions have `_fixed` suffix)
- Fixed transcripts are fully compatible with the standard viewer
- The thinking content is preserved exactly as generated by the target model
- This works for any Petri audit where the target uses `<thinking>` tags
